Architecture notes

// how I think

Go Boilerplate

Goal: start new services with production defaults already in place instead of rebuilding the same infrastructure decisions from scratch.

Tradeoff: a little more setup up front, but the payoff is consistent service boundaries, testable modules, and fewer ad hoc decisions under delivery pressure.

Rusty Requester

Goal: make an API client that feels native and disposable, so opening it for a quick request does not cost hundreds of megabytes or a full browser-stack boot.

Tradeoff: less plugin ecosystem than Postman, but much better startup feel, lower memory use, and tighter local-only ownership of request data.

Routing Engine for Reachable Listings

Goal: replace a gothere-dependent commute backend and 16-hour precompute flow with self-hosted routing and live reachability on your own infra.

Tradeoff: owning Valhalla + GTFS means a harder data pipeline, but it unlocks provider independence, measurable calibration, and better control over transit correctness and matrix refreshes.

Heart Disease KNN Flask

Goal: turn a machine-learning study into a usable web application so heart-disease prediction is not just a notebook result but something practical to interact with.

Tradeoff: KNN is simple and interpretable, but preprocessing matters heavily. In the paper, z-score normalization raised accuracy from 65.93% to 82.41%, which became the key implementation lesson.

Blog MCP Server

Goal: give AI clients retrieval access to my own technical writing so answers can be grounded in my material instead of generic model priors.

Tradeoff: retrieval quality depends on chunking and indexing choices, so the interesting work is less “AI magic” and more practical search behavior.
